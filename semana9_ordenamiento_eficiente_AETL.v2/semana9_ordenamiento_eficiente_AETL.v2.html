1. El Paradigma Divide y Vencerás

Divide y Vencerás (D&V) es un paradigma de diseño de algoritmos que opera en tres pasos recursivos:

⚙️ Los tres pasos de Divide y Vencerás

1. DIVIDIR: Partir el problema en subproblemas más pequeños del mismo tipo.

2. CONQUISTAR: Resolver cada subproblema de forma recursiva. Cuando el subproblema es suficientemente pequeño (caso base), resolverlo directamente.

3. COMBINAR: Fusionar las soluciones de los subproblemas para construir la solución del problema original.

La clave del salto de complejidad está en el árbol de recursión. Si cada nivel del árbol hace trabajo proporcional a n, y el árbol tiene altura log₂(n) (porque dividimos a la mitad en cada paso), el trabajo total es O(n · log n).

2. Merge Sort — Dividir con precisión, combinar con orden

Merge Sort divide el arreglo en mitades hasta llegar a subarreglos de un elemento (ya ordenados por definición), y luego fusiona los pares ordenados construyendo arreglos ordenados cada vez más grandes.

┌─────────────────────────────────────────────────────────────────────┐ │ ÁRBOL DE RECURSIÓN — MERGE SORT │ │ Arreglo: [8, 3, 1, 5, 2, 7, 4, 6] │ ├─────────────────────────────────────────────────────────────────────┤ │ │ │ DIVIDIR ↓ [8, 3, 1, 5, 2, 7, 4, 6] n=8 │ │ / \ │ │ [8, 3, 1, 5] [2, 7, 4, 6] n=4 │ │ / \ / \ │ │ [8, 3] [1, 5] [2, 7] [4, 6] n=2 │ │ / \ / \ / \ / \ │ │ [8] [3] [1] [5] [2] [7] [4] [6] n=1 (BASE) │ │ │ │ COMBINAR ↑ │ │ [3,8] [1,5] [2,7] [4,6] n=2 │ │ \ / \ / │ │ [1, 3, 5, 8] [2, 4, 6, 7] n=4 │ │ \ / │ │ [1, 2, 3, 4, 5, 6, 7, 8] n=8 │ │ │ │ Altura del árbol = log₂(8) = 3 niveles │ │ Trabajo por nivel = O(n) — cada elemento se toca una vez en merge │ │ Total = O(n · log n) │ └─────────────────────────────────────────────────────────────────────┘
Explicación: El árbol muestra las dos fases de Merge Sort. Hacia abajo (DIVIDIR): el arreglo se parte en mitades recursivamente hasta llegar a subarreglos de un solo elemento — el caso base. Hacia arriba (COMBINAR): la función merge() fusiona pares de subarreglos ya ordenados, comparando elemento a elemento y colocando el menor primero. Cada nivel del árbol procesa en total n elementos, y hay log₂(n) niveles, de ahí O(n log n). Nota crítica: Merge Sort requiere un arreglo auxiliar del mismo tamaño que el original para la fusión — complejidad de espacio O(n).
✅ Invariante de Merge Sort

Al terminar cada llamada a merge(izq, der), el segmento resultante siempre está correctamente ordenado. Esto es verdad sin importar qué contenían los subarreglos de entrada — siempre y cuando ellos mismos estuvieran ordenados. La fusión preserva el orden.

Pseudocódigo: Merge Sort

función merge_sort(arr, inicio, fin): si inicio >= fin: // Caso base: 0 o 1 elemento retornar medio ← (inicio + fin) // 2 // Punto de división merge_sort(arr, inicio, medio) // Conquistar: mitad izquierda merge_sort(arr, medio + 1, fin) // Conquistar: mitad derecha merge(arr, inicio, medio, fin) // Combinar: fusionar ordenado función merge(arr, inicio, medio, fin): // Crear copias temporales de ambas mitades izquierda ← arr[inicio .. medio] derecha ← arr[medio+1 .. fin] i ← 0; j ← 0; k ← inicio mientras i < longitud(izquierda) y j < longitud(derecha): si izquierda[i] <= derecha[j]: // Estabilidad: <= preserva orden relativo arr[k] ← izquierda[i]; i ← i + 1 sino: arr[k] ← derecha[j]; j ← j + 1 k ← k + 1 // Copiar elementos restantes (ya están en orden) mientras i < longitud(izquierda): arr[k] ← izquierda[i]; i ← i + 1; k ← k + 1 mientras j < longitud(derecha): arr[k] ← derecha[j]; j ← j + 1; k ← k + 1 // Complejidad tiempo: O(n log n) — todos los casos (mejor, promedio, peor) // Complejidad espacio: O(n) — arreglos auxiliares izquierda y derecha // Estabilidad: SÍ — elementos iguales mantienen su orden relativo original

def bubble_sort_s8(arr: list) -> None:
    """Referencia de Semana 8 para comparación empírica."""
    n = len(arr)
    for i in range(n):
        for j in range(n - i - 1):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]


def medir_tiempo(func, arr: list, *args) -> float:
    """Mide tiempo sobre una copia — el arreglo original no se modifica."""
    copia = copy.deepcopy(arr)
    inicio = time.perf_counter()
    func(copia, *args)
    fin = time.perf_counter()
    return round(fin - inicio, 6)

El Problema que Merge Sort No Resuelve

Merge Sort garantiza O(n log n) en tiempo para todos los casos. Sin embargo, la función merge() requiere crear copias auxiliares de cada subarreglo antes de fusionarlos. En cada nivel del árbol de recursión se usan colectivamente O(n) bytes de memoria adicional.

⚠️ El cálculo de RAM que rechazó Sofía

StreamMX tiene 4 000 000 de registros. Cada registro contiene: ID (8 bytes), título (50 bytes promedio), puntaje (8 bytes), fecha (8 bytes) y metadatos (50 bytes) ≈ 124 bytes por registro.

RAM del dataset original: 4 000 000 × 124 = ~496 MB

RAM adicional por Merge Sort (O(n)): otros ~496 MB durante la fase de fusión más costosa

Total en el peor momento: ~992 MB — casi 1 GB extra solo para ordenar

Con un servidor que tiene 1.5 GB de RAM total compartida con otros servicios, esto colapsa el sistema. El tiempo mejoró de 47 min a 3 min, pero la disponibilidad del servidor se rompió.

📖 Glosario — Semana 9

Divide y Vencerás (D&V)
Paradigma de diseño que parte un problema en subproblemas del mismo tipo, los resuelve recursivamente y combina las soluciones. Base de Merge Sort (Semana 9) y Quick Sort (Semana 10).
Merge Sort
Algoritmo de ordenamiento estable O(n log n) en todos los casos. Divide el arreglo en mitades recursivamente y fusiona subarreglos ordenados. Requiere O(n) espacio auxiliar.
Árbol de Recursión
Representación visual de las llamadas recursivas. Para Merge Sort, tiene altura log₂(n) y cada nivel procesa colectivamente O(n) elementos → O(n log n) en total.
Invariante de merge()
Al terminar cada iteración del ciclo de fusión, el segmento arr[inicio..k-1] contiene los k−inicio elementos más pequeños de las dos mitades, correctamente ordenados.
Estabilidad
Propiedad que garantiza que elementos con claves iguales mantienen su orden relativo original. Merge Sort es estable por el uso de <= en la comparación de fusión.
Espacio Auxiliar O(n)
Memoria adicional proporcional al tamaño del arreglo que Merge Sort requiere para sus arreglos temporales durante la fusión. Es la limitación que motiva Quick Sort (Semana 10).
In Situ (In-Place)
Propiedad de un algoritmo que opera usando O(1) o O(log n) espacio adicional. Merge Sort no es in-place. El algoritmo in-place con O(n log n) promedio se estudia en Semana 10.
Quick Sort / Pivote / Partición ← Semana 10
Estos conceptos se estudian e implementan la semana siguiente como respuesta a la restricción de RAM que Merge Sort deja abierta. Anticipación: requiere O(log n) espacio y ordena in-place.
