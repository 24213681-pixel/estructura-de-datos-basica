1. Búsqueda lineal — O(n)

La búsqueda lineal no requiere ninguna condición previa sobre el arreglo. Recorre cada elemento de izquierda a derecha hasta encontrar el objetivo o agotar el arreglo. Su invariante es trivial: "los elementos desde el inicio hasta la posición actual no son el objetivo."

BÚSQUEDA LINEAL sobre A = [ 12 7 3 19 5 8 14 2 ] Objetivo: buscar 8 ═══════════════════════════════════════════════════════ i=0: A[0]=12 ≠ 8 → continuar i=1: A[1]=7 ≠ 8 → continuar i=2: A[2]=3 ≠ 8 → continuar i=3: A[3]=19 ≠ 8 → continuar i=4: A[4]=5 ≠ 8 → continuar i=5: A[5]=8 = 8 → ¡ENCONTRADO en posición 5! Comparaciones realizadas: 6 Peor caso (no está en el arreglo): 8 comparaciones = n Buscar 99 (no existe): i=0,1,2,3,4,5,6,7 → 8 comparaciones → retornar -1
La búsqueda lineal recorre el arreglo [12, 7, 3, 19, 5, 8, 14, 2] elemento por elemento buscando el valor 8. Realiza 6 comparaciones antes de encontrarlo en la posición 5. Si el objetivo no existe (como el 99), hace exactamente n = 8 comparaciones y retorna -1. No requiere que el arreglo esté ordenado.

2. Búsqueda binaria — O(log n)

La búsqueda binaria requiere arreglo ordenado como condición previa. En cada paso, compara el objetivo con el elemento central y descarta la mitad del espacio de búsqueda.

⛔ Precondición no negociable
Si el arreglo no está ordenado, búsqueda binaria puede retornar "no encontrado" aunque el elemento esté presente, o encontrar un elemento en la posición incorrecta. No hay mecanismo interno que detecte este error — el resultado simplemente es incorrecto en silencio. El HITO 2 depende de que el pipeline ordene primero.
BÚSQUEDA BINARIA sobre A = [ 2 3 5 7 8 12 14 19 ] (ordenado) Objetivo: buscar 8 → n=8, peor caso = ⌊log₂(8)⌋+1 = 4 comparaciones ═══════════════════════════════════════════════════════════════════════ Iteración 1: izq=0 der=7 mid=(0+7)//2=3 A[3]=7 < 8 → objetivo está a la DERECHA de mid Nuevo izq = mid+1 = 4 Espacio restante: A[4..7] = [ 8 12 14 19 ] Iteración 2: izq=4 der=7 mid=(4+7)//2=5 A[5]=12 > 8 → objetivo está a la IZQUIERDA de mid Nuevo der = mid-1 = 4 Espacio restante: A[4..4] = [ 8 ] Iteración 3: izq=4 der=4 mid=(4+4)//2=4 A[4]=8 = 8 → ¡ENCONTRADO en posición 4! Comparaciones: 3 (vs 5 con búsqueda lineal sobre el mismo objetivo) ────────────────────────────────────────────────────────────────────── Buscar 6 (no existe): Iter 1: mid=3, A[3]=7 > 6 → der=2, espacio A[0..2] Iter 2: mid=1, A[1]=3 < 6 → izq=2, espacio A[2..2] Iter 3: mid=2, A[2]=5 < 6 → izq=3 izq(3) > der(2) → BUCLE TERMINA → retornar -1 Comparaciones: 3 (peor caso con n=8: máximo 4)
La búsqueda binaria opera sobre el arreglo ordenado [2, 3, 5, 7, 8, 12, 14, 19]. En la primera iteración, calcula el índice central (mid=3, valor 7) y determina que 8 está a la derecha porque 7 < 8. Mueve izq a mid+1=4. En la segunda iteración, mid=5 (valor 12), 12 > 8, mueve der a mid-1=4. En la tercera, mid=4 (valor 8), coincide con el objetivo. Total: 3 comparaciones. Para el valor inexistente 6: 3 comparaciones y el bucle termina cuando izq > der.

3. Pseudocódigo y invariante de búsqueda binaria

PSEUDOCÓDIGO — Búsqueda Binaria (versión iterativa) ═══════════════════════════════════════════════════════ función busqueda_binaria(A, objetivo): izq ← 0 der ← longitud(A) - 1 mientras izq ≤ der: mid ← (izq + der) // 2 # ¡División entera! si A[mid] == objetivo: retornar mid # Posición encontrada si A[mid] < objetivo: izq ← mid + 1 # Descartar mitad izquierda si no: der ← mid - 1 # Descartar mitad derecha retornar -1 # No encontrado ═══════════════════════════════════════════════════════ ADVERTENCIA — Errores comunes de implementación: ❌ mid = (izq + der) / 2 → en Python retorna float, no int ✅ mid = (izq + der) // 2 → división entera obligatoria ❌ izq ← mid (sin +1) → bucle infinito cuando izq==der ✅ izq ← mid + 1 → siempre reduce el espacio ❌ der ← mid (sin -1) → bucle infinito cuando izq==der ✅ der ← mid - 1 → siempre reduce el espacio ❌ while izq < der → pierde el caso de un solo elemento ✅ while izq <= der → cubre A[i..i] correctamente ────────────────────────────────────────────────────────────────────── 🌐 FORMA CANÓNICA EN CIENCIAS DE LA COMPUTACIÓN (todos los lenguajes): Python 3 tiene enteros de precisión arbitraria → (izq + der) // 2 nunca desborda. En C, C++ y Java los int tienen 32 bits (máx ≈ 2 147 483 647). ❌ mid = (izq + der) // 2 → en C/Java: overflow si izq+der > INT_MAX ✅ mid = izq + (der - izq) // 2 → forma canónica — segura en todo lenguaje Este bug destruyó Arrays.binarySearch() del JDK durante 20 años (1986–2006). La forma canónica se usa como hábito profesional aunque Python no la exija.
El pseudocódigo muestra la versión iterativa de búsqueda binaria. Los errores más comunes incluyen: usar división flotante en lugar de entera (//), no avanzar izq/der más allá de mid (deben ser mid+1 y mid-1), usar izq < der en lugar de izq <= der, y en C/C++/Java calcular mid como (izq+der)/2 que puede causar integer overflow para arreglos grandes. La forma canónica izq + (der - izq) // 2 es segura en cualquier lenguaje.
🛠️ Advertencia de Ingeniería Real — El bug de búsqueda binaria más famoso de la historia

En junio de 2006, Joshua Bloch (autor de Effective Java y miembro del equipo de Java en Sun Microsystems) publicó un post que sacudió a la comunidad: la implementación de Arrays.binarySearch() en el JDK tenía un bug desde 1986 — 20 años sin que nadie lo notara.

El problema era exactamente la línea que ustedes acaban de estudiar:

// Java — JDK hasta 2006 (BUGGY):
int mid = (low + high) / 2;   // ← overflow si low + high > Integer.MAX_VALUE (2 147 483 647)

// Java — forma corregida (canónica en CS):
int mid = low + (high - low) / 2;  // ← nunca desborda, funciona siempre

El bug no se disparaba con arreglos pequeños — solo con arreglos de más de 2³⁰ ≈ 1 000 000 000 elementos. En 1986 esos arreglos no existían; en 2006, con servidores de producción con gigabytes de RAM, empezaron a aparecer.

Python 3 los protege: sus enteros no tienen límite de bits (son BigIntegers implícitos), así que (izq + der) // 2 nunca desborda en Python. Pero como programadores de LSC trabajarán en C, C++ y Java donde int tiene exactamente 32 bits. La forma canónica izq + (der - izq) // 2 es un hábito profesional, no un capricho académico.

📐 Invariante de búsqueda binaria

Invariante del bucle: Si el objetivo existe en el arreglo A, entonces A[izq..der] lo contiene. Más precisamente:

  • Al inicio de cada iteración: si objetivo ∈ A, entonces objetivo ∈ A[izq..der].
  • Cuando A[mid] < objetivo: objetivo no puede estar en A[0..mid], por lo que movemos izq = mid + 1 sin perder el invariante.
  • Cuando A[mid] > objetivo: objetivo no puede estar en A[mid..n-1], por lo que movemos der = mid - 1 sin perder el invariante.
  • Cuando izq > der: el espacio de búsqueda está vacío — el objetivo no existe. Retornamos -1.

Por qué funciona: en cada iteración el espacio de búsqueda se reduce estrictamente a la mitad (o menos). El número máximo de iteraciones es ⌊log₂(n)⌋ + 1. Para n = 5 000 000: ⌊log₂(5 000 000)⌋ + 1 = 22 + 1 = 23 comparaciones.

💡 Límites fundamentales de búsqueda binaria

La búsqueda binaria es óptima para búsqueda en arreglos ordenados — ningún algoritmo puede garantizar menos de ⌊log₂(n)⌋ comparaciones en el peor caso. Sin embargo tiene tres restricciones que la hacen inadecuada en algunos contextos:

  • Requiere orden previo: si los datos cambian frecuentemente, el re-ordenamiento puede costar más que las búsquedas que ahorra.
  • Requiere acceso aleatorio: funciona con arreglos pero no con listas enlazadas (sin acceso a A[mid] en O(1)).
  • Peor caso O(log n), no O(1): en catálogos con millones de búsquedas por segundo, incluso 23 comparaciones por búsqueda pueden ser demasiadas.

📖 Glosario — Semana 11

Búsqueda lineal
Algoritmo que recorre el arreglo de izquierda a derecha comparando cada elemento con el objetivo. O(n) en tiempo, O(1) en espacio. No requiere orden. Apropiada para arreglos pequeños o búsquedas únicas sobre datos no ordenados.
Búsqueda binaria
Algoritmo que divide el espacio de búsqueda a la mitad en cada iteración, basándose en la comparación del objetivo con el elemento central. O(log n) en tiempo, O(1) en espacio (versión iterativa). Requiere arreglo ordenado como precondición.
Invariante de búsqueda binaria
Propiedad preservada en cada iteración del bucle: si el objetivo existe en A, entonces está contenido en A[izq..der]. Al terminar el bucle con izq > der, el espacio está vacío — el objetivo no existe.
Precondición
Condición que debe ser verdadera ANTES de llamar a una función para que su comportamiento sea correcto. La precondición de búsqueda binaria es que el arreglo esté ordenado ascendentemente. Violarla produce resultados incorrectos en silencio.
Amortización
Análisis del costo promedio de una operación cuando se repite muchas veces. En el HITO 2, el costo de ordenar (O(n log n)) se "amortiza" entre las k búsquedas binarias que lo siguen. A partir de un número K de búsquedas, el pipeline siempre es más barato que k búsquedas lineales.
Pipeline ordenar → buscar
Diseño arquitectónico del HITO 2: primero se ordena el catálogo una vez (O(n log n)) y luego todas las búsquedas subsecuentes son O(log n). El costo de ordenar se paga una vez; la ganancia en búsqueda se acumula.
Off-by-one error
Error de implementación donde se usa mid en lugar de mid+1 o mid-1, causando que el espacio de búsqueda nunca se reduzca en ciertos casos (bucle infinito) o que se descarte el elemento objetivo. El error más común en implementaciones de búsqueda binaria.
